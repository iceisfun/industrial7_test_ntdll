# Export surface evidence

- Source: `GET /api/modules/ntdll/exports?limit=1000&offset={0,1000,2000}` on the Windows corpus API. The complete response is retained in `tools/ntdll_exports.json`: 2,433 records, 2,432 named, ordinal-only export 8, no forwarders.
- `reference.inc` is generated by `python3 tools/generate_export_table.py`. Resolve-only sweeps never call unknown signatures or count as behavioral coverage.
- Nt/Zw address equivalence is asserted in strict-reference mode only, for pairs whose reference records have the **same RVA**, not merely similar names. Other hosts may use different entry stubs; their differences are observations. This is user-mode image evidence, not an assertion that kernel Nt/Zw PreviousMode semantics are interchangeable. For example, the retained manifest records `NtClose` (ordinal 262) and `ZwClose` (1847) at RVA `0x9d230`, and `NtCreateFile` (288) and `ZwCreateFile` (1873) at `0x9daf0`.
- The host table consistency test checks PE name/ordinal resolution against the loaded host's own export table. It never requires host RVAs or ordinal assignments to match a different build.
- Default reference sweep records absences as observations. Set `NTDLL_STRICT_EXPORTS=1` **only on the exact reference DLL version 10.0.19041.2788** to assert all baseline names and name/ordinal mappings, including ordinal 8. An ordinal's presence on another build says nothing about its signature or identity.
